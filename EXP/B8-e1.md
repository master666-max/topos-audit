## 3. 三句实话（本批最值钱的部分）

### ① recall 恰好等于"看了多少" —— 零富集

| 臂 | 核验比例 | recall |
|---|---|---|
| a | 23.85% | **0.2385** |
| b | 49.86% | **0.4986** |
| c | 100% | **1.0000** |

三个数**一模一样**。`k / 阳性总数` = `核验单元 / 全部单元`，**误差为 0**。
⇒ 在当前信号源下，这条流水线**等价于"随机抽一批人来肉看"**。
它唯一的价值退化为"决定看哪一批"，而"看哪一批"目前是**等宽顺序块**（等于随机）。

### ② 放宽宽度买到的只是"看得更多"，不是"看得更准"

臂 a → 臂 b 把宽度从 22 放到 46，核验从 176 涨到 368，recall 从 0.2385 涨到 0.4986——
**但 AUC 一个小数点都没动（0.4986 → 0.4986）**，平衡准确率恒为 0.5000。
这正是 `PREREG/B8.md` T-B8-c 要求同时报的代价：**别只报好处**。

### ③ anchor 正则作为"检测器"，已被**三次独立实测**证伪

| # | 实测 | 结论 |
|---|---|---|
| 1 | SVEN 配对判别力 win 0 / loss 8，符号检验 **p=0.0078 显著反向** | 反向 |
| 2 | B6 副靶 AUC **0.5001** | 抛硬币 |
| 3 | **B8 臂 c（100% 覆盖）AUC 0.5036** | 抛硬币 |

三次独立、三种口径，**结论一致**。anchor 正则只能当**注意力分配**（把人引到哪去看），
**不能当检测器**（判断这里有没有问题）。这条应当写进 `README` 与 `regex.py` docstring。

## 4. D-B6-5 对照臂在本靶**不成立**（如实登记）

`grep` 只命中 **67 个单元**，凑不满 176 的同预算 ⇒ 两边核验量**不对等**
（流水线 176 vs grep 67），k 无法同口径比较（88 vs 31）。
**不得据此宣称"流水线优于 grep"。** 对照臂需在主靶（完整仓库）上重做才有效。

## 5. 登记盲区

1. **靶是"脱水的"**：SVEN = 从真实项目抠出的孤立函数，无 git、无文件内多函数结构。
   本批所有读数**只对该靶负责，不外推**。主靶 L1（112 缺陷）仍未跑（需下载源码）。
2. **性能**：单次 Space 构建 17m42s（738 单元）。N=10⁴ 预算仍是 [U]，未实测。
3. 等宽顺序块在真实仓库上可能把同一文件的函数聚在一块，影响"池内 OR"语义——
   本批不修（属 DEFERRED 岗位二的补池策略）。
4. **本批没有让机器变聪明，只是证明了它现在有多笨。** 这是 B6 立项时就要的那个读数。

## 4. 未确认边分类（分类器 `EXP/_m5_e2_classify.py` + 人工抽验）

未确认 = T−Gm。机械分类：GAP=金标侧有该调用点痕迹但 callee 未解析（调用真实存在）；
FP=金标（含未解析层）无任何痕迹/查实为撞名误解析。**GOLD=0（两靶映射零异常）。**

| 靶 | 未确认 | GAP（金标盲区） | FP（topos 真误报） |
|---|---|---|---|
| py | 65 | **63** | **2** |
| js | 8 | **5** | **3** |

**py GAP 63 条**（机械标签 + 抽验为真）：pysrc2cpg 对动态分发（`self.x()`、`ctx.x()`、
`utils.check_ast_node(arg)` 等参数对象/模块别名调用）一律不解析 callee → 注册口径
（仅取 resolved）下不可指认。抽验：`cli/main.py::main → BanditConfig.get_option`
（`conf.get_option(...)`）、`gen_blacklist → build_conf_dict`（模块别名属性调用）等均为源码实有调用。

**py FP 2 条（人工定谳）**：
- `issue_from_dict → Cwe.from_dict`：源码 `i.from_dict(data)`——动态分发撞名，topos 猜到
  Cwe（应为 Issue 同类方法）——简单名解析的固有边界；
- `checks → check_ast_node`：调用真实（`utils.check_ast_node(arg)`）但真 owner 是嵌套
  `wrapper` 单元——py 侧同款嵌套归因现象（F3 修复仅做了 js 侧）。

**js GAP 5 条（逐条源码验证）**：
- `links → get`：`var link = this.get('Link')`（response.js:99）✓ 真调用；
- `format → vary`：`this.vary("Accept")`（:585）✓ 真调用，callee 恰为 `res.vary`@878；
- `format → normalizeType / normalizeTypes`：`normalizeType(key)`（:588）、`normalizeTypes(keys)`
  （:594）✓ 真调用（经 `require('./utils')` 裸别名）；**jssrc2cpg 对该形态连 CALL 节点都
  未建**（dump 中零痕迹）——金标盲区中最深一档；
- `stringify → cookie`：res.cookie 体内 `stringify(val, …)` 真调用（无向对）✓。

**js FP 3 条（人工定谳，单一根因）**：`accepts → acceptsEncodings / acceptsCharsets /
acceptsLanguages`——npm 包名 `accepts`（`var accepts = require('accepts')`，request.js:16）
与方法 `req.accepts`（:127）**撞名**；`req.accepts` 本体（127-129）不调这三者，真 callee 是
npm 模块函数，topos 简单名解析优先同文件 → 假边。喂 v0.2：require 别名表应含裸模块名的
"外部名清单"，同名同文件单元让位。

## 8. 教训登记

1. **修 bug 会跌门**：F1 修复使 py precision 0.8065→0.7421 跌破 0.8——修复前的"过门"是
   少报虚高。校验器视角：**先修被校验件，再看读数**；门上的数字不许为过门而保留缺陷。
2. **阈值教训第三 sister**：无新拍阈值，但 precision 门 0.8 本身也是未实测拍的——被
   金标盲区占比打穿。任何门的分母宇宙必须先实测其可达性。
3. **对拍脚本自检**：本会话诊断阶段内联"复刻"脚本因参数错位（`tfn` 误当文件名）得出
   Gm=0 的假矛盾，浪费数轮——**复刻对拍代码同样必须过突变自检**（v1.0 已做，教训是
   临时诊断脚本也要做）。

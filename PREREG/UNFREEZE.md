## 2. 必须钉住的一条：解冻防的是什么

**冻结条款防的是"自欺"，不是"线上事故"。**

用户的反驳（"又不是生产环境"）**成立**——把科研/工具类项目的排程按生产发布的风险等级来管，是错配。
但**自欺风险与是否生产环境无关**，它来自"参照物漂移"：判据改了四版、轴加到十个、而"找到几个真 bug"始终没被评过。

因此：**取消 T-B6-a 之后，原来由"不许开工"承担的防护，全部转由 T-B6-b..f 承担。**

| 条款 | 内容 | 是否受解冻影响 |
|---|---|---|
| ~~T-B6-a~~ | ~~冻结：出读数前禁开工~~ | **取消** |
| **T-B6-b** | 禁自指参照：判据参照物必须是真实缺陷（L1/L3），不得是另一仪器/合成数据/本仓绿灯 | **不变** |
| **T-B6-c** | 禁调参到咬合：清单/阈值/预算一旦冻结，不得因检出结果不佳而修改后重跑 | **不变** |
| **T-B6-d** | 禁合并平均：逐项目逐臂打行，禁止先合并再判 | **不变** |
| **T-B6-e** | 禁措辞升格：k=0 必须写"在 n 个已知缺陷中找到 0 个" | **不变** |
| **T-B6-f** | 禁把过程当产出：跑通/零退出/schema 合法/自检全绿都不是产出 | **不变** |

**一句话**：解冻允许你**同时开工**，但不允许你**用开工代替称货**。D-B6-1..5 一次都不能少跑。

## 4. 登记盲区（解冻的代价，见数据前认下）

1. **并行开工 ⇒ 归因困难**：多层修复与检出评测同时跑，若检出读数变化，**无法干净归因**是 α 接线还是新场带来的。缓解：每个改动单独留一份 `space.json` 快照，逐项对照。

4. 解冻**不影响** L4 欠账：Se/Sp 仍未标定，Sp 甚至不可估（`DECISIONS-PENDING.md` D2）。

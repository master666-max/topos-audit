## 1. 操作化定义（锁定）

### 1.1 被评对象 = 完整流水线，不是单个部件

固定五步序列，全部按默认口径跑：

```
space（建空间）→ 池设计 → 观测（信号源给每池 yes/no）→ decode（后验）→ next/stop（选下一池）
```

### 1.2 清单冻结时点（防"把靶的信息喂进设计"）

RUN1 的教训：清单迭代三轮才把覆盖调到能用（96.4% → 88.4% → 90.4%），而每次迭代的依据里
混进了 belief 与命中读数。本批规定：

- 起跑用**仓内默认 `axes.json`**；
- **允许一次清单调整**，但必须在**看到任何检出结果之前**完成并落盘冻结（记 `manifest_frozen_sha`）；
- 调整理由**只许引用覆盖诊断**（`zero_cover_rate` / `c_min` / 池宽），
  **不许引用** belief、命中数、任何单元名。违反即整批作废。

### 1.3 单元对齐（禁模糊匹配）

L1 的 `unit_id = "<path>::<Class.func>:<lineno>"`（`calib/patch_extract.py:153`）与本仓
`Space.units` 的 id（`core/units.py:64`）**同构**，故按 id 精确对齐。

- **禁止**文件级或函数名级模糊匹配（会把"同文件里另一个函数"算成命中）。
- 对齐**双向报**：真值侧未匹配数（= 分母缩水量）与检出侧未匹配数。
- 分母一律从**对齐后的集合现读**，不许手写常数（手写 112 而对齐后只剩 97 是典型假总数）。

### 1.4 三个信号源臂（分开报，禁止合并）

| 臂 | 观测源 | 说明 |
|---|---|---|
| **A** | anchor 正则（现状默认，33 tag） | 确定性信号，零成本 |
| **B** | LLM 批审（每池一次 yes/no） | 模型档/端点/提示词/温度**全冻结并落盘**；跑前记 sha |
| **C** | A + B 双源 | 检验"两源是否真独立"——B2-E4 已实测三个同源 LLM 裁判 α=0.187、阳性交集 0，本臂给一个**非自指**的复现位 |

### 1.5 预算

固定 **8 次开池**（对齐 B4 的 k=8 口径，可与 `EXP/b4_e1.json` 的模拟读数并列比较，但**不得并表**：
那边真值是植入的，这边是真 bug）。

## 2. 判据（只有这五个出口读数，别的都不是判据）

| # | 判据 | 内容 | 门槛 |
|---|---|---|---|
| **D-B6-1** | **检出** | 在 L1 已知缺陷函数上报 **k/n 召回**，逐臂逐项目打行 | **A 臂 k ≥ 1**。门槛低到刺眼是故意的——现值可能是 0，而"这台仪器能不能找到已知 bug"至今**没有答案**；先要知道是不是 0 |
| **D-B6-2** | **误报** | 报误报数 m 与 m/(k+m)，**逐条给证据**（file:line + 判读理由） | 不设阈值。理由：无真值的负样本上"误报率"不可信（§8 真值不可得条款在此适用） |
| **D-B6-3** | **覆盖（守门读数）** | 已知缺陷函数中"被至少一个池覆盖"的比例 | **≥ 50%**。理由：召回 ≤ 覆盖，覆盖不到 50% 时召回读数无解释力（k=0 可能只是"没看过"）。**不达标 ⇒ D-B6-1 全部标"不可解释"，整批判为"设计矩阵不合格"，转 B7 修覆盖后重跑** |
| **D-B6-4** | **单位预算产出** | k/8（每开一池找到几个）+ 每池人工核验单元数 | 不设门槛，只报。这是唯一能与"grep + 人读"同口径比较的读数 |
| **D-B6-5** | **对照臂（无此臂则整批无意义）** | `grep -rn` 同一批危险 API + 人工读**同样 8 批**单元，报同样的 k/n | **流水线 k 必须 > grep 臂 k** |

**D-B6-5 不咬合的处置（本批最重要的一句）**：如实报"混检流水线在此靶上不优于 grep"。
**这本身就是本批最有价值的读数**——不许改写、不许补池、不许调清单后重跑、不许降格成"登记盲区"。

**副靶**：L3 SVEN 368 对（有正有负）⇒ 可算平衡准确率与 AUC。**只作旁证**，不进主判据
（域窄 9 类 CWE、自带 94% 精度声明，见 §6）。

## 4. 禁止条款

- **T-B6-a（冻结条款 · 本批第一红线）**：D-B6-1..5 出读数之前，**禁止开工任何
  "加场 / 加轴 / 换解码器 / 改停止判据 / 改抽取器"的批次**。已写好的两份草案已改名留档
  （见页首"本件取代"），号位让出，内容不删。
- **T-B6-b（禁自指参照）**：本批任何判据的参照物**必须是真实缺陷**（L1/L3）。
  禁止用"另一个仪器同意我""合成数据里我恢复了真值""我的自检全绿"充当出口读数。
- **T-B6-c（禁调参到咬合）**：清单（§1.2）、阈值、预算一旦冻结，**不得因检出结果不佳而修改后重跑**。
  若确需修改：旧读数改名 `-VOID` 留档并列可比，修订计入 §5 上限，且必须在修订日志里写明
  "本次修订发生在看到 k=? 之后"。
- **T-B6-d（禁合并平均）**：逐项目、逐臂打行；禁止先合并再判（合并掩盖单靶失效）。
- **T-B6-e（禁措辞升格）**：k=0 的表述必须是"在 n 个已知缺陷中找到 0 个"，
  **不得写成"未发现漏洞""零确认漏洞""可放心使用"**。RUN1 的措辞是反面教材
  （`RUN1-dsh-final.md:82-84`：零确认漏洞 ⇒ "该仓可放心继续用"）。
- **T-B6-f（禁把过程当产出）**：跑通、零退出、schema 合法、自检全绿——**这些都不是产出**。
  产出只有 §2 那五个读数。

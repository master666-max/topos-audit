## 1. 要改的两处（最小改动，一次只动一个变量）

### 1.1 停止前置门（三态，不是两态）

`next` 的输出从 {NEXT, STOP} 扩为 **{NEXT, STOP, BLOCKED-COVERAGE}**：

```
若 zero_cover_rate > θ_cov  → 输出 BLOCKED-COVERAGE（既不是 NEXT 也不是 STOP）
                              并印：未覆盖单元数 / 已覆盖单元数 / θ_cov / 需要补的池数下界
否则                        → 走原 σ 判据，输出 NEXT 或 STOP
```

- **θ_cov 见数据前写死 = `0.30`**。
  理由：E-X1 的 [M] 读数是**11.5% 零覆盖就已导致散布缺陷不可检出**；0.30 是宽松档，
  先让门在真仓上能过、能开始产出读数，再逐批收紧。**阈值只许向前收紧，绝不许放宽**（T-B7-a）。
- **不许静默回落**：θ_cov 缺失或非法 ⇒ **raise**，不给默认值
  （对齐 `report/json_out.py:36-38` 的"缺失即 bug，不存在可选优化"）。
- **BLOCKED-COVERAGE 不是失败态也不是观察态**，它是一个**有内容的结论**：
  "以当前设计矩阵，本仪器无权对未覆盖部分下任何判断"。

### 1.2 报告口径

- `json_out` / `md_out` 增两个**必填**字段：`covered_units`、`zero_cover_units`
  （缺字段即 raise，与现有 `REQUIRED_COVERAGE_KEYS` 同款契约）。
- 覆盖不足时，报告**首行强制印**：
  > 本次审计未覆盖 X%（N 个单元），以下结论**不适用于**该部分。
- **任何全仓断言（"零漏洞""可放心使用""该仓干净"）必须由覆盖率背书**；
  覆盖率 < 100% 时**禁止输出全仓断言**（现实上不可能 100%，故等价于禁止全仓断言）。

### 1.3 本批**不做**的事（防混轴）

不动 σ 公式、不动解码器、不加场、不改抽取器、不修 CLI 与 `budget.py` 之间
已知的停止判据版本分叉（`cli.py:162-166` 仍用 B4-v1.3 已作废的 confirmed 语义——
**该缺陷单独开单，不并入本批**，否则一处改动两个变量、归因失效）。

## 4. 禁止条款

- **T-B7-a（阈值只向前）**：θ_cov 只许收紧（0.30 → 0.20 → …），**绝不许放宽**。
  要放宽必须上报裁决并**点明利益冲突**——被门管的人没有放宽门的权力。
- **T-B7-b（禁降格）**：BLOCKED-COVERAGE **不得**被降格成 OBSERVED / N/A / "观察项"
  而在报告里消失（这是 2026-09-26 犯过的三种自作主张之一，写进本仓纪律）。
- **T-B7-c（禁混轴）**：本批只动 §1.1 与 §1.2 两处。任何"顺手修一下别的"都使归因失效。
- **T-B7-d（禁覆盖历史读数）**：重跑前先复制成 `-pre` / `-VOID`；被覆盖的数不许再引。
- **T-B7-e（禁把门当产出）**：门修好、c35–c37 全绿——**这些不是产出**，产出是 D-B7-5 那份报告里的
  发现条数与覆盖事实。
